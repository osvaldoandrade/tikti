# Migration 0007 — SAML user fields

## Purpose

Adds `authSource` and `externalSubject` to every existing user record
stored in the `users_v2` Redis hash. Pre-existing production tenants carry
user documents without these fields; this migration backfills safe defaults
so that downstream code can rely on their presence.

| Field             | Default value | Description                              |
|-------------------|---------------|------------------------------------------|
| `authSource`      | `"password"`  | How the user was provisioned             |
| `externalSubject` | `""`          | SAML NameID — empty for password users   |

## Running

```bash
# The migration is invoked programmatically:
go run ./cmd/tikti-migrate-0007

# Or within a test harness:
go test -count=1 -run TestMigration ./migrations/...
```

## Behaviour

1. `HSCAN` iterates the `users_v2` hash with `COUNT 500`.
2. For each user record the JSON is decoded.
3. If `authSource` is already set the record is **skipped** (idempotent).
4. Otherwise `authSource` is set to `"password"` and the record is written
   back with `HSET`.
5. A Prometheus counter `tikti_migration_0007_records_total{result}` is
   incremented for every record with label `result` ∈ {`updated`, `skipped`,
   `error`}.

A second run produces **zero** `updated` increments.

## Rollback

Rollback removes the two fields from every user document. It is **not**
executed automatically — invoke `Down()` explicitly if you need to revert.

```go
import "github.com/osvaldoandrade/tikti/migrations"

err := migrations.Down(ctx, redisClient)
```

### Manual rollback via redis-cli

```bash
# For each user in the hash, strip the two fields from the JSON payload.
# This is a destructive operation — take a snapshot first.
redis-cli BGSAVE

# Then iterate and patch (pseudo-code):
# for each field in HSCAN users_v2 0 COUNT 500:
#   json = HGET users_v2 <uid>
#   remove .authSource and .externalSubject from json
#   HSET users_v2 <uid> <patched_json>
```
